# Contributing to PG Food Brands repositories

Thank you for contributing. These defaults apply when a repository does not provide more specific instructions.

## Before you start

- Read the repository `README`, `AGENTS.md`, and any local contribution or security guidance.
- Confirm the intended behavior and keep the change focused on one outcome.
- Use a descriptive branch name with a conventional prefix such as `feature/`, `fix/`, `chore/`, or `docs/`.
- Never commit credentials, tokens, customer data, production exports, or other confidential material.

## Make and validate the change

- Follow the repository's existing structure and conventions.
- Add or update tests when they provide meaningful coverage for the changed behavior.
- Run the checks documented by the repository and report the commands and results in the pull request.
- Update operational or user documentation when behavior, configuration, deployment, or rollback steps change.

## Open a pull request

Explain what changed, why it is needed, how it was validated, and any deployment or rollback considerations. Link the relevant issue or internal work item when one exists.

Keep commits reviewable and do not push directly to protected branches. Address review comments and keep required checks green before merge.

## Report security issues privately

Do not disclose suspected vulnerabilities in an issue, discussion, pull request, commit message, or build log. Follow the repository security policy or the organization default in [SECURITY.md](SECURITY.md).
